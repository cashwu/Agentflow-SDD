# Cash Skill Lint

修訂 `SKILL.md` 或 `scripts/cash-skills/blocks/` 下的 block 檔時，逐條走過以下六種失效模式。這是人工檢核維度，不是阻斷性的自動化檢查——回歸套件不含以本清單為依據的斷言。每條有三部分：**定義**說明失效長什麼樣、**症狀**是可在檔案裡看到的具體形狀、**檢查問句**是修訂時要對自己問的話。

詞彙以 [`CASH-GLOSSARY.md`](../../CASH-GLOSSARY.md) 為準。

## premature completion

**定義**：指令在 agent 真正滿足目標之前就允許它宣告完成。門檻寫得比意圖低，或驗證步驟被寫成可選。

**症狀**

- 標記完成的步驟沒有指名驗證證據（測試、CLI、analyzer 或人工斷言）。
- 出現「if time permits」、「盡量」、「視情況」這類把必要步驟降級為選項的措辭。
- 完成條件只描述動作發生過（「執行 X」），不描述結果成立（「X 通過且輸出為 Y」）。
- 多步驟流程只在最後一步驗證，中間步驟的失敗會被後續步驟蓋掉。

**檢查問句**

- 這個步驟的完成判準是可觀察的結果，還是只是「做過了」？
- 如果 agent 在這裡停下並宣告完成，使用者拿到的東西會少什麼？
- 有沒有哪個 MUST 沒有對應的失敗路徑？

## duplication

**定義**：同一條規則以逐字或近似的形式存在於多個位置，靠人工同步維持一致。任何一處修訂都會製造漂移。

**症狀**

- 同一段規格文字出現在兩個以上的 `SKILL.md`。
- 同一個數字、路徑或識別字在多份文件各自寫死。
- 規則旁邊附註「記得同步更新 X」。
- 兩個變體各自維護同一段內容，而非由生成器產出。

**檢查問句**

- 這條規則的唯一維護處在哪裡？
- 如果只改這一處，其他地方會自動跟上，還是會靜默不一致？
- 這段重複能不能改由 block 檔或轉換規則承接？

## sediment

**定義**：舊決策的殘留物在新決策之後仍留在檔案裡。指令沒有被取代，只是被繞過，於是同一份檔案同時描述兩套做法。

**症狀**

- 指向已移除機制、檔案或旗標的引用。
- 兩段指令對同一情境給出不同處置，且沒有標明何者優先。
- 「（舊做法）」、「已不再使用」這類註記留在正文而非被刪除。
- 名稱仍反映舊模型（例如檔案已改為生成輸出，敘述仍稱其為 canonical）。

**檢查問句**

- 這段文字描述的是現在的行為，還是曾經的行為？
- 上一次改動這個機制時，有沒有 grep 全部引用面？
- 如果一個沒有歷史脈絡的人只讀這份檔案，會不會做出已被否決的選擇？

## sprawl

**定義**：檔案因逐次追加而膨脹，每次追加都局部合理，整體卻讓 agent 難以定位當下需要的那一段。

**症狀**

- 同一個主題散在多個不相鄰的段落。
- 章節標題無法預測其內容，或層級深到需要回頭確認上下文。
- 為單一罕見情境新增的例外條款與主線規則等長。
- 讀完整份檔案才知道某個步驟其實不適用當前情境。

**檢查問句**

- 這段新增內容屬於既有章節，還是真的需要自己的位置？
- agent 要執行第 N 步時，需要記住前面幾段？
- 這個例外值得寫進主線，還是屬於它自己的 skill？

## no-ops

**定義**：讀起來像指令、但不改變任何行為的文字。它佔用 context 卻不產生決策差異。

**症狀**

- 「仔細思考」、「注意品質」、「保持嚴謹」這類沒有可檢查判準的勸勉。
- 重述模型預設行為的指令。
- 沒有對應處置的觀察陳述（描述了一個情境卻不說要做什麼）。
- 條件永遠成立或永遠不成立的分支。

**檢查問句**

- 刪掉這一行，agent 的行為會有什麼具體差異？
- 這句話有沒有指名一個可觀察的判準或一個明確動作？
- 這是在描述行為，還是在描述態度？

## negation

**定義**：只說不要做什麼，不說要做什麼。agent 知道被禁止的路徑，卻沒有被指向可行的路徑。

**症狀**

- 一連串 `MUST NOT` 之後沒有對應的正面指令。
- 「不要猜」、「不要假設」後面沒有接「改為執行 X」。
- 禁令描述的錯誤做法比正確做法更具體，agent 只學到反面樣本。
- 例外條款只說明不適用，不說明改走哪條路。

**檢查問句**

- 這條禁令有沒有配對的正面路徑？
- agent 讀完這段後，知道下一步要做什麼嗎？
- 如果把所有 `MUST NOT` 蓋掉，剩下的文字還能完成任務嗎？
